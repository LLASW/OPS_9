## OPS9 工程（STM32F103 + HAL + MDK）代码解读与风险排查（未改代码）

项目定位：纯「里程计/位姿板」，无电机 PWM 输出。
- TIM1(PA8)/TIM4(PB6) 外部时钟模式计脉冲 + PA9/PB7 方向电平 → 双路里程轮（App/encoder.c）
- USART3 + DMA1_Ch3 ReceiveToIdle 收 WIT 陀螺仪 11 字节角度帧 → yaw（App/imu.c）
- 轮速 + yaw 做航迹推算，积分出 x/y/z（App/ops9_control.c）
- USART2 以 0x5C 头 + float x/y/z + CRC8 上报；收 0xC5+data 命令，0x22 = 软件复位

### 排查出的主要风险（按严重度）
1. `IMU_zero_angle()` 从未执行：`IMU_para.yaw` 初值 0，`while(yaw!=0)` 立即跳过；若真进入则是无超时死循环 + 浮点判 0；0x76 在 REG.h 中是 XRSCALE 而非 Z 轴归零命令。
2. `Control_task()` 里 `ops9_direction = dirt;` 被注释 → 上位机方向命令完全无效，恒为 2。
3. USART2 单缓冲发送无 TX 完成判定 + 14B@115200≈1.22ms > 主循环≈1.1ms → 帧内容被中途改写（上位机 CRC 错）+ 周期性丢帧。
4. 接收状态机「吞字节」：数据字节后进入 state2，必须再来一个字节才提交 → 单帧命令永不生效；连续流约丢一半命令。
5. `yaw_add_count()` 的 static `yaw_last` 初值 0 → 首帧真实 yaw 触发错误 ±2π 展开，初始航向偏近 π。
6. 命令无 CRC/范围校验：`ops9_direction` 非法时 switch 无 default，`chassis_line` 残留 → 位置无限漂移；0x22 可被噪声误触发复位。
7. delay.c（正点原子）与 HAL 共用 SysTick：`delay_init` 改源为 HCLK/8，`delay_ms` 每次改 LOAD 并关计数器 → HAL 时基基本失效。
8. IMU 看门狗 `get_data_flag` 置 1 后永不清零，掉线后 yaw 冻结仍继续积分。
9. IMU 帧只判 `[1]==0x53`，不校验帧头/SUM；工程已移植 wit_c_sdk 却未用 `WitSerialDataIn`。
10. 编码器：读 CNT 后置 0 丢脉冲；用 `HAL_TIM_Encoder_Start` 启动外部时钟模式计数（应 Base_Start）；无输入滤波；方向电平只采样瞬间。
11. 优势：位移积分链路 `count/1024*2π*R` 中 dt 被约掉，结果与主循环周期无关。

用户要求：先只做解读与问题排查，不改代码。

## 追加：改造后框架解读（用户问"现在工程的运作框架及优缺点"）

当前框架 = **TIM3 1ms 硬件 tick + 协作式周期调度器 + 全非阻塞任务**：
- 时基：TIM3 PSC71/ARR999 → 1ms 溢出 → `HAL_TIM_PeriodElapsedCallback` → `OS_ClockInterruptHandle()` 只置 `RunFlag`
- 前台：`OS_Start()` → `OS_TaskRunOnce()` 按枚举顺序（Odom 5ms → Report 10ms → Background 10ms）执行到期任务
- 关键性质：**周期准确（计数基于硬件 tick，不累积漂移），但相位有抖动（顺序遍历、无抢占，前序任务耗时推迟后序）**；
  任务执行超时不会排队，只会丢拍（RunFlag 被覆盖合并）
- 中断只做三件事：TIM3 置标志、USART2 RX 收字节/TX 清忙、USART3 DMA TC 绕圈计数；业务全在任务上下文
- 三条数据流：编码器(TIM1/TIM4 外部时钟 + 方向 GPIO) → Odom 5ms 采样积分；USART3 环形 DMA → BG 10ms 解析 yaw；
  USART2 100Hz 上报 14B 帧(约 12% 带宽)

已识别的主要短板：协作式无抢占（单任务卡死会拖垮全部）、`OS_Start()` 空转 100% CPU、
200Hz 采样下换向符号窗口 5ms、256B 缓冲满码流仅 22ms 而 BG 可能被推迟、
IMU 掉线无上报/无位姿清零手段、归零未记 frame_cnt 基线、robot_com 接收状态机吞字节（与 ABC 同款）。

- 低功耗方案 A **已落地后又按用户要求完整回退**（`App/os_task.c` 删除 `OS_AnyTaskReady()`，`OS_Start()` 恢复紧循环；
  `os_task.h` 注释同步还原）。`main.c` 的 `HAL_DBGMCU_EnableDBGSleepMode()` 自始至终未加。
  → 当前 CPU 恢复 100% 空转，SWD 正常。后续若要重新启用，改动点见本条记录。

Keil microlib 不支持 `sprintf("%f")`，显示浮点要改成整数格式化；`OLED_I2C_WaitIdle()` 无超时死等需补超时+总线恢复。
